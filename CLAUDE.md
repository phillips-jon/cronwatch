# CronWatch

Monorepo: `packages/sdk` (`@cronwatch/sdk`), `packages/mcp` (`@cronwatch/mcp`), `packages/ruby` (the `cronwatch` gem, a port of the SDK; see its `DESIGN.md`), `site` (cronwatch.dev, static), `skills/cronwatch` (a Claude Code skill), `deploy` (server scripts for the site).

- Use Node 24 (`.nvmrc`); better-sqlite3 13 needs Node 22 or newer. Run `npm run check` before committing: it runs the dash check, typecheck and tests. Postgres store tests run when `CRONWATCH_TEST_PG` is set; CI provides one.
- No em or en dashes anywhere in the repo, including docs and commit messages. `scripts/check-dashes.mjs` gates build and test.
- The SDK core has no dependencies beyond `croner`. Drivers (`better-sqlite3`, `pg`, `@anthropic-ai/sdk`) are optional peers, imported only from their own entry points and kept `external` in `tsup.config.ts`.
- The Ruby gem follows the SDK. A behaviour change lands in TypeScript first, then `npm run conformance` regenerates `conformance/` (and, for the routes or pages, `TZ=UTC node packages/ruby/test/web/golden.mjs` regenerates the dashboard fixture), and the gem is fixed until `bundle exec rake test` (in `packages/ruby`, after `npm run build`) passes. `npm run check:conformance`, part of `npm run check`, fails on either stale fixture. The gem supports Ruby 3.2 or newer and Rails 7.2, 8.0 and 8.1; `packages/ruby/test/rails/gemfiles` has a Gemfile per Rails series, and `packages/ruby/README.md` has the testing details.
- Alert logic lives in `packages/sdk/src/evaluate.ts` as pure functions; keep side effects in `client.ts`. Every condition opens once and closes with a recovery; do not add repeat alerts without a design discussion.
- The site is hand-written HTML and CSS plus markdown docs built by `site/build.mjs` (marked only). Fonts are self hosted woff2 in `site/src/assets/fonts` (Newsreader for anything a person reads, IBM Plex Mono for anything a machine printed), so the CSP is `'self'` throughout and the page fetches from no other origin. The landing page is set like a printed sheet in neutral greys (colour only for the states the library reports): light by default (dark is the toggle), a serif for prose, and a small mono label down the left of each section. Its spine is the dashboard's last-24-hours timeline and jobs board, shown in a flat browser frame and redrawn as SVG by `build.mjs` from the captured page `site/src/demo/dashboard.html`; every mark, alert, reply and board row that claims to be output comes from the captures in `site/src/demo` (`node site/scripts/demo.mjs --capture`, run with `TZ=UTC` after building the packages), never hand-written. Concept illustrations (the checks diagram, the hosted-versus-library diagram) may be drawn by hand in `build.mjs`, as long as they are labelled as illustrations and keep to the same thin lines, mono labels and state colours. The CSP forbids inline styles and scripts: no `style=""` attributes, all CSS in `site/src/style.css`, script only in `site.js`, `theme.js` and `search.js` (the docs search, whose index `build.mjs` writes as a script because `connect-src` is `'none'`). Motion is CSS, starts when `site.js` sees a figure scroll into view, and is off under `prefers-reduced-motion`. No gradients (the one exception is the logo mark's box in the header, by the owner's choice), glows, shadows, eyebrow badges or pills. `npm run dev:site` serves the site with live rebuild; `npm run dev:dashboard` serves a dashboard of dummy jobs.
- Deploys: once CI passes on a push to `main`, the deploy workflow runs `deploy/release-deploy` on the server via a command-locked SSH key. Nothing is deployed until the repository variable `DEPLOY_ENABLED` is `true`.
- Releases: `npm run release -- <version>` (try `--dry-run` first) bumps every versioned file, runs the checks, builds the gem and checks its file list, commits and tags; it never pushes or publishes. A new package under `packages/` gets a row in both tables at the top of `scripts/release.mjs` (`VERSIONED` and `PUBLISH`); the script refuses to run without them.
- Commits: short messages, no attribution lines. Review the full diff before committing.
