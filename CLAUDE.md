# CronWatch

Monorepo: `packages/sdk` (`@cronwatch/sdk`), `packages/mcp` (`@cronwatch/mcp`), `packages/ruby` (the `cronwatch` gem, a port of the SDK; see its `DESIGN.md`), `site` (cronwatch.dev, static), `skills/cronwatch` (a Claude Code skill), `deploy` (server scripts for the site).

- Use Node 24 (`.nvmrc`); better-sqlite3 13 needs Node 22 or newer. Run `npm run check` before committing: it runs the dash check, typecheck and tests. Postgres store tests run when `CRONWATCH_TEST_PG` is set; CI provides one.
- No em or en dashes anywhere in the repo, including docs and commit messages. `scripts/check-dashes.mjs` gates build and test.
- The SDK core has no dependencies beyond `croner`. Drivers (`better-sqlite3`, `pg`, `@anthropic-ai/sdk`) are optional peers, imported only from their own entry points and kept `external` in `tsup.config.ts`.
- The Ruby gem follows the SDK. A behaviour change lands in TypeScript first, then `npm run conformance` regenerates `conformance/`, and the gem is fixed until `bundle exec rake test` (in `packages/ruby`) passes. The SDK check fails on stale fixtures (`npm run check:conformance`, part of `npm run check`).
- Alert logic lives in `packages/sdk/src/evaluate.ts` as pure functions; keep side effects in `client.ts`. Every condition opens once and closes with a recovery; do not add repeat alerts without a design discussion.
- The site is hand-written HTML and CSS plus markdown docs built by `site/build.mjs` (marked only). Fonts are self hosted woff2 in `site/src/assets/fonts` (Newsreader for anything a person reads, IBM Plex Mono for anything a machine printed), so the CSP is `'self'` throughout and the page fetches from no other origin. The landing page is set like a printed sheet in neutral greys (colour only for the states the library reports): light by default (dark is the toggle), a serif for prose, and a small mono label down the left of each section. Its spine is a strip of one day's recorded runs, drawn as SVG by `build.mjs` from `site/src/demo/runs.json`; every mark, alert, reply and board row comes from the captures in `site/src/demo` (`node site/scripts/demo.mjs --capture`, run with `TZ=UTC` after building the packages), never hand-written. No gradients, glows, eyebrow badges or pills.
- Deploys: once CI passes on a push to `main`, the deploy workflow runs `deploy/release-deploy` on the server via a command-locked SSH key. Nothing is deployed until the repository variable `DEPLOY_ENABLED` is `true`.
- Commits: short messages, no attribution lines. Review the full diff before committing.
